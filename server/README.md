# Сервер LOKO RUSH

Сервер гри для онлайн-режиму: вхід через Telegram, профіль онлайн-клубу в базі, власний сервер PeerJS і тимчасові паролі до ретранслятора coturn. Сторінки гри цей сервер не роздає: вони й далі на GitHub Pages.

Що вже є:

- `POST /auth/telegram` перевіряє підпис Telegram (`initData`) токеном бота гри й видає сесію на 30 днів.
- `GET /me` повертає гравця і його онлайн-клуб.
- `POST /club` створює клуб за правилами гри (`newClub` із `src/online/profile.js`); повторний виклик повертає наявний. Монети записуються в журнал `coin_ledger`.
- `GET /turn` видає пароль до coturn на 6 годин лише гравцеві, що увійшов.
- `POST /share/room` готує в боті картку виклику в кімнату (`savePreparedInlineMessage`), а гра відкриває її у вікні «Поділитися» (`shareMessage`).
- `POST /tg` це вебхук бота гри (секрет у заголовку, без загального ліміту частоти).
- `/p/` (через Caddy) це сервер PeerJS, що знайомить гравців онлайн-матчу.

**Онлайн-хаб (API 2).** `GET /health` віддає `{ ok, api: 2, features }`, і гра вмикає кожну частину лише за її назвою; без назви лишається локальна логіка. Правила (нагороди й Ело `applyResult`, ціни, герої, квести) сервер бере з гри через `src/rules.js`, кожна зміна монет пише рядок у `coin_ledger`.

- `club` (`src/hub/club.js`): `POST /club/save` перший раз переносить клуб із пристрою, обрізаючи прогрес до заявлених матчів (`w + d + l = games`; монети до min(20 000, 300 + 200·games), рейтинг до min(2400, 1000 + 40·games), рівень до 1 + ⌈games/2⌉, голи до 15·games, навички до бази рідкості + 28 + games, не більше 99; чистить `fromWire`); обрізане пишеться у `flags`, далі приймає лише вигляд, схему й порядок тих самих героїв (воротар на 0). `POST /club/train`, `/club/scout`, `/club/reset`, `/club/pack` (рідкісний чи епічний пак: ціни й шанси з `PACKS` і `packRarity` гри; маршрут з'являється, лише коли вони є в `src/online/profile.js`). `GET /me` додає `rank`, `live` (матч без звіту) і `quests`.
- `match` (`src/hub/match.js`): господар кличе `POST /match/start { code, role: 'host', mode }` і отримує `{ matchId, ticket }`; квиток (18 випадкових байтів, у базі лише хеш) живе 120 с, господар шле його гостю P2P, а гість приходить `{ role: 'guest', ticket }`. За кодом кімнати не паруємо: код знає кожен, кому його надіслали. Повтор гостя з тим самим квитком дає той самий матч, чужий гравець чи господар із ним отримують `bad_ticket`/`self`; без гостя за 120 с матч `solo` (сервер його не рахує). `POST /match/result` і `GET /match/:id`: дзеркальні звіти підтверджують рахунок господаря, розбіжність дає `disputed` (рейтинг без змін, обом 30 монет), вихід (`forfeit: 'me'`) це технічна поразка одразу, звіт одного гравця стає підсумком через 60 с, а за 15 хв без звітів матч закривається (серверний `settleLive`). Від фарму: рахунок раніше 200 с після парування — `disputed`; рейтингових матчів однієї пари не більше 3 за київську добу, далі `limited: true` і лише 30 монет за участь; монети платяться не більше ніж за 8 голів. Фонова перевірка `sweep` іде раз на 30 с.
- `quests` (`src/hub/quests.js`): ті самі квести, що в грі (`src/online/quests.js`); прогрес лише в підтвердженні дограного матчу, `GET /quests`, `POST /quests/claim`, незабране з минулих періодів зараховується само (`banked`). Частина вмикається лише тоді, коли в гілці є `src/online/quests.js` з чистими експортами (`rules.QUESTS`).
- `queue` (`src/hub/queue.js`): `POST /queue` (довге очікування до 12 с), `/queue/leave`, `GET /queue/stats`. Черга лише в пам'яті: вікно рейтингу ±100, +25 кожні 5 с до ±400, після 40 с будь-хто; господар той, хто довше чекав; `avoid` і пара з недавньою розбіжністю не зводяться; хто не питав 20 с, випадає. `opp.id` і `avoid` — непрозорий id (HMAC секрету сервера, 12 знаків), а не Telegram ID.
- `flags`: журнал підозрілого для власника (`import`, `disputed`, `pair`, `fast`), `SELECT * FROM flags ORDER BY at DESC`. Забанених (`players.banned`) не пускає `auth`, у таблиці й черзі їх немає.
- Сервер кімнат PeerJS (`src/peerguard.js`): з однієї адреси не більше 40 нових WebSocket і 120 спроб з'єднатися (OFFER) за хвилину, тож перебір 5-знакових кодів кімнат марний. Ліміт у самому процесі, а не в Caddy: стандартний Caddy без `caddy-ratelimit` не вміє, а nftables не відрізнить `/p/` від API на тому самому 443.
- `shop` (`src/hub/club.js`, частина вмикається, коли в `src/online/profile.js` є `packInto`, `sellFrom`, `lineupOk`): лава запасних до 5 героїв. `POST /club/buy { hero, pack }` кладе новачка з паку на лаву (позиція — слот `hero`), `POST /club/sell { id }` продає героя з лави, склад разом із лавою приходить у `POST /club/save` і приймається лише з тими самими героями й воротарем на 0 (`lineupOk`). Матч нагороджує лише основу, лаву зберігає як є.
- `top` (`src/hub/top.js`): `GET /top?limit=50` → `{ list, me }`, лише клуби, що є в грі (`imported_at`).

Чого ще немає: турнірів (формат вирішує власник), ринку. Віджет рейтингу бота ще показує й клуби, створені `POST /club` і ні разу не відкриті в грі.

## Контракт онлайн-хабу (API 2)

Клієнт уже написаний під цей контракт (`src/online/server.js`, `src/online/cloud.js`). Частини сервер вмикає по одній: `GET /health` → `{ ok, api: 2, features: [...] }`. Частину, якої немає в `features`, гра робить на пристрої, як раніше. Правила беруться з гри через `rules.js`, своїх формул на сервері немає. Кожна зміна монет пише рядок у `coin_ledger`.

| Частина | Маршрути | Що робить сервер |
|---|---|---|
| `club` | `POST /club/save`, `GET /me`, `POST /club/train`, `/club/scout`, `/club/reset` | Перший `save` переносить клуб із пристрою з `base` (ліміти: монети ≤ 20 000, рейтинг 0–2400; чистить `fromWire`). Далі приймає лише вигляд, схему й порядок героїв за `id`. Монети, рейтинг, рівні й навички рахує сам. Відповідь `{ club }` у будові `/me → club`: `{ club, heroes, bench, xp, rec, goals, games, coins, rating, lvl }`. `train { hero, stat, id? }` (hero — номер у списку «основа, потім лава»; `id` важливіший) і `scout` повертають `{ coins, hero }`. `POST /club/pack { hero, pack }` (старий шлях без лави): пак `rare` чи `epic` за `PACKS` і `packRarity`, новий герой міняє героя слота. Помилки `no_coins`, `max`, `bad_hero`, `bad_stat`, `bad_pack`, `no_club`. |
| `shop` | `POST /club/buy { hero, pack }`, `POST /club/sell { id }`; склад із лавою — через `POST /club/save` (`heroes` + `bench`) | Лава запасних до `BENCH_MAX` = 5. Пак (`scout`, `rare`, `epic`) кладе новачка на позицію слота `hero` на лаву: `packInto` гри, номер з 12. Відповідь `{ coins, hero, bench, club }`, помилки `no_coins`, `bench_full`, `bad_pack`, `bad_hero`. Продаж лише з лави за `sellPrice` гри (`SELL[rar]` + 5 за очко рейтингу понад базу рідкості) → `{ coins, gain, club }`, помилки `not_bench`, `bad_hero`. Склад і лава в `save` приймаються, лише якщо це ті самі герої за `id` і `lineupOk` (воротар на 0 і лише там). Журнал: `pack`, `scout`, `sell`. Лаву при першому перенесенні обрізають ті самі межі, що й основу. |
| `match` | `POST /match/start`: господар `{ code, role: 'host', mode }` → `{ matchId, ticket }`, гість `{ role: 'guest', mode, ticket }` → `{ matchId }` (квиток 24 знаки, у базі хеш, 120 с; гість ≠ господар; за кодом не парує; помилки `bad_ticket`, `self`; без гостя за 120 с матч `solo`). Обмеження: рахунок раніше 200 с — `disputed`; з 4-го матчу пари за київську добу `limited: true` (30 монет, без рейтингу й квестів); монети за голи не більше ніж за 8. Підозріле пишеться в таблицю `flags`. PeerJS: ≤ 40 нових WebSocket за хвилину з адреси (`peerguard.js`). Черга віддає лише непрозорий `opp.id`, `POST /match/result { matchId, me, opp, scorers, forfeit?, void? }`, `GET /match/:id` | Парує господаря й гостя за одноразовим квитком господаря (120 с). Звіти збігаються: підтверджено. Розбіжність: `disputed`, без рейтингу, обом 30 монет за участь. Мовчить гість: вірить господарю. Мовчить господар, а гість звітує `forfeit: 'opp'`: технічна перемога гостя. Ніхто не звітував 15 хв: поразка мовчазному. Нагороди як `applyResult`, Ело з K = 32 за серверними рейтингами. Відповідь `{ state, rew, quests, club }` або `{ state: 'wait' }`. |
| `queue` | `POST /queue { code, avoid? }` (довге очікування ≤ 12 с), `/queue/leave`, `GET /queue/stats` | Черга в пам'яті. Вікно рейтингу ±100, ширшає на +25 за кожні 5 с, до ±400; після 40 с годиться будь-хто. Господар той, хто довше чекав. Відповідь `{ state: 'wait', searching }` або `{ state: 'paired', role, code, opp: { id, name, rating } }`. |
| `quests` | `GET /quests`, `POST /quests/claim { period, id }` | Ті самі квести, що в грі (`questPeriods`, `dayIds`, `weekIds`, `questDef`, `questStep`, `factsOf` із `src/online/quests.js`). Прогрес рахує підтвердження матчу, технічні результати не рахуються. Незабране зараховується, коли змінився період (`banked`). |
| `top` | `GET /top?limit=50` | `{ list: [{ place, name, flag, rating, lvl, w, d, l }], me: { place, rating } }`. |
| `cups` | пропозиція: `GET /cups`, `/cups/:id`, `POST /cups/:id/join`, `/leave`, `/ready` | Формат вирішує власник. Клієнта для турнірів ще немає. Нічия в кубку потребує серії пенальті в онлайні (зміна клієнта й `PROTO`). |

Таблиці бази:
- `matches`, `match_reports`, `quests(player_id, period, id, p, got_at)`;
- для кубків `cups`, `cup_entries`, `cup_games`;
- у `clubs` колонка `imported_at`.

Обмеження, які впливають на дизайн:
- `api.requestTimeout` 15 с;
- CORS лише `GET` і `POST`, тож скасування теж через `POST`.

Порядок робіт: `club` + `match`, далі `quests`, `queue`, `top`, `cups`.

## Бот гри

Той самий процес обслуговує бота з `BOT_TOKEN` (`src/bot/`). Telegram шле оновлення на `https://<DOMAIN>/tg`; без `PUBLIC_URL` (локально) бот сам опитує Telegram.

- `/start` — обкладинка гри (`store/telegram-cover-640x360.png`, вантажиться раз, далі за `file_id`) і меню: «Грати» (Mini App), «Мій клуб», «Рейтинг», «Кинути виклик другу», «Як грати». `/start room_КОД` веде прямо в кімнату.
- `/club` — картка онлайн-клубу: прапор, рівень, рейтинг, монети, перемоги-нічиї-поразки, три найсильніші герої, місце в рейтингу. У приватному чаті картка сама оновлюється, коли з'являється на екрані.
- `/top` — рейтинг: один спільний віджет на всіх, кожна копія бачить свіжі дані; у кожному чаті ще й «Твоє місце».
- Inline-режим (`@бот` у будь-якому чаті) і кнопка «Поділитися» в лобі гри: картка виклику з гербом суперника, кодом кімнати й кнопкою «Прийняти виклик».
- Профіль бота (команди, описи українською й англійською, кнопка меню «Грати») сервер ставить сам і лише коли тексти змінились (`src/bot/texts.js`).

**Віджети.** Картки — HTML-віджети в повідомленні (Bot API 10.4, `sendWidget`, [widget-sandbox](https://github.com/TelegramMessenger/widget-sandbox)): `src/bot/widgets/*.html`, кожен до 4 КБ стиснутого (тест `bot.test.js` це перевіряє). Вони лише малюють стан, що пише бот (`chat_data`, `public_data`), мережі не мають. Якщо Bot API ще не знає `sendWidget`, бот годину шле те саме текстом і пробує знову; клієнти без віджетів бачать підпис. `BOT_WIDGETS=0` вимикає віджети зовсім, `BOT_API_URL` задає інший сервер Bot API (наприклад бета `https://api.telegram.org/beta`).

**У BotFather:** аватар (`public/icon-512.png`), Main Mini App на адресу гри (кнопки «Грати» і посилання `?startapp`), `/setinline` з підказкою «код кімнати» (виклики в чатах). Решту бот налаштовує сам.

## Навантаження і збої

Сервер стоїть поруч із ботом LOKO (2 ядра, 4 ГБ), і бот головніший.

- **Процесор і пам'ять.** `loko-game` має вагу процесора 50 проти 100 у бота, не більше одного ядра, 300 МБ м'якої й 400 МБ жорсткої стелі пам'яті та першим гине при нестачі пам'яті. coturn, Caddy і Litestream мають ті самі ваги й по 256 МБ (`deploy/limits.conf`). Додатково swap на 1 ГБ і журнал усього сервера не більше 500 МБ.
- **Ретранслятор.** Більшість матчів іде напряму, через coturn лише ті, кому заважає NAT. Обмеження: 160 КБ/с на з'єднання (матч шле ~64 КБ/с), 6 МБ/с разом, 100 з'єднань, 4 на гравця. Понад це гравці йдуть через публічний ретранслятор PeerJS.
- **Запити.** Гра тримає сесію 30 днів у `localStorage` і паролі ретранслятора 6 годин, тож до API звертається хіба при першому вході й раз на кілька годин гри. Сервер приймає до 120 запитів на хвилину з адреси (вхід: 20), до 5 сесій на гравця і до 1000 одночасних гравців у сервері кімнат.
- **Сервер упав.** Гра це помічає (тайм-аут 4–6 с), хвилину його не чіпає й відкриває кімнату на публічному PeerJS, як до появи сервера. Гість шукає кімнату на обох. systemd перезапускає службу через 5 с і ніколи не здається.
- **Копії бази.** Щоночі (03:00–08:00 за Києвом, не перетинається з нічною роботою бота о 01:15) цілісна копія в `/opt/loko-game/data/backups`, 14 днів. Це захист від поломки бази, але не від втрати диска. Від втрати диска захищає Litestream: копія в Backblaze B2 (бакет `loko-rush-gamedb`, приватний, старі версії файлів видаляються через добу). Ключ лише до цього бакета лежить у `/etc/loko-game/backup.env` (доступ тільки root), install.sh його підхоплює. B2 дає 10 ГБ безкоштовно й без картки, запис безкоштовний; синхронізація раз на 10 с. Підійде й Cloudflare R2, якщо вписати його `LITESTREAM_*`.
- **Оновлення пакетів.** Node.js і Caddy зі сторонніх сховищ теж оновлюються самі через unattended-upgrades.

## Локально

Потрібен Node.js 24 (база це вбудований `node:sqlite`).

```bash
cd server
npm install
npm test
BOT_TOKEN=123:abc ALLOWED_ORIGINS=http://localhost:5173 npm start
```

## На сервері

Потрібні домен або піддомен, що вказує на сервер, і бот гри в BotFather.

```bash
curl -fsSL https://raw.githubusercontent.com/Alexpro121/loko-rikoshet/main/server/deploy/install.sh -o install.sh
sudo DOMAIN=api.приклад.ua GAME_ORIGIN=https://alexpro121.github.io bash install.sh
```

Перший запуск створить `/etc/loko-game/env` і зупиниться: впишіть `BOT_TOKEN` і запустіть ще раз. Скрипт ставить Node.js, Caddy, coturn, службу `loko-game` з обмеженнями (див. нижче), swap і відкриває у фаєрволі 80, 443, 3478 і діапазон портів ретранслятора 49160–49359/udp. Якщо в `env` заповнено `LITESTREAM_*`, він ще й налаштує безперервну копію бази в Cloudflare R2 чи Backblaze B2.

Скрипт ставить і залежності кореня репозиторію без dev (`three` тощо): правила гри, які імпортує сервер, тягнуть модулі гри.

**Зараз працює:** `https://2-29-117-47.sslip.io` (безкоштовна адреса sslip.io, що вказує на IP сервера; сертифікат Let's Encrypt), бот `@lokorush_bot`. Свій домен: змініть `DOMAIN`, `PUBLIC_URL` і `TURN_URLS` в `/etc/loko-game/env`, запустіть оновлення й впишіть нову адресу в `SERVER_URL`.

Оновлення до свіжого коду (підтягує код і заново застосовує налаштування служб, без apt):

```bash
sudo bash /opt/loko-game/app/server/deploy/update.sh
```

Після запуску впишіть адресу сервера в `SERVER_URL` у `src/online/server.js` і опублікуйте гру: до того гра працює з публічним PeerJS, як раніше.
